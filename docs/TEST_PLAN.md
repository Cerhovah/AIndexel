### §11.2 공개 URL E2E

테스트 입력은 실제 M5 배포 작업과 커밋 `9719e65`에 근거한 새 기록이다. 테스트는 권한을
`0700`으로 제한한 임시 브라우저 프로필에서 수행했으며, 완료 후 프로필과 다운로드를 삭제했다.

| 순서 | 확인 내용 | 실제 결과 | 판정 |
|---:|---|---|---|
| 1 | 공개 URL 접속 및 설정의 APP_TOKEN 저장 | 배포 화면 로드, 저장 상태 `저장됨` | 통과 |
| 2 | 원문·source 입력 후 실제 분석 | 실제 Worker 분석 성공 | 통과 |
| 3 | summary / feedback / next 표시 | 3개 모두 표시, 각 300자 이하 | 통과 |
| 4 | 기록 저장 | IndexedDB에 새 ID 1건 생성, `저장됨` 표시 | 통과 |
| 5 | 페이지 새로고침 후 유지·재발견 | 같은 ID 유지, 검색 결과에서 재발견 | 통과 |
| 6 | 상세 펼치기 | 3문장·구조화 색인·execution_summary·decisions·원문·판본 표시 | 통과 |
| 7 | source_locator 원위치 | 입력한 GitHub 커밋 URL과 링크가 일치 | 통과 |
| 8 | 전체 JSON 내보내기 | `workindex_backup_YYYYMMDD.json` 다운로드, 새 기록 포함 | 통과 |
| 9 | 다른 기록 삭제 후 새로고침 | 복제본의 기존 기록 삭제가 유지되고 새 기록은 보존 | 통과 |
| 10 | §11.2 전체 흐름 | 중단 없이 완료 | 통과 |

추가로 80,000자는 잘리지 않고 분석 가능했으며, 80,001자는 그대로 유지된 채 분석이
비활성화되고 `80,000자를 넘습니다. 나눠서 넣어 주세요.`가 표시됐다. 사이트 IndexedDB만
복제한 프로필을 Chrome 프로세스 종료 후 새 프로세스로 다시 열었을 때 기록 수와 ID 집합도
동일했다.
